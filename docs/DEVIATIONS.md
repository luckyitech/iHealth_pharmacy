# Deviations from the legacy system

Every intentional difference in behaviour between the legacy iHealth system and this rebuild, and why.
Each entry names where it is implemented. Add a row with every pull request that changes behaviour.

| Area                                            | Legacy behaviour                                                                                                                               | New behaviour                                                                                                                                                                                | Why                                                                                                                             | Where                                                                                                   |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Permissions                                     | Checked in the Angular app only, by position in a list (`permissions[25]`)                                                                     | Checked by the API on every request, by `PHARMA_ACCESS_ID`                                                                                                                                   | Browser checks can be bypassed; positions break when rows change                                                                | `apps/api/src/features/auth/auth.guards.js`, `@ihealth/shared/permissions`                              |
| Role permissions                                | None (only per-employee grants)                                                                                                                | `ih_role_permission`, empty by default                                                                                                                                                       | Role-based access without changing existing grants                                                                              | `apps/api/db/sql/additive/0001-auth.sql`                                                                |
| Password storage                                | BCrypt or plain text in `employee_credentials`                                                                                                 | argon2id in `ih_employee_password`, upgraded at sign-in; the legacy column is never written                                                                                                  | Plain text is unacceptable for health data; the legacy app keeps working                                                        | `apps/api/src/features/auth/auth.service.js`                                                            |
| Session                                         | JWT readable by page scripts                                                                                                                   | httpOnly cookies, 15-minute access token, rotating refresh token, CSRF token                                                                                                                 | XSS cannot steal the session; stolen refresh tokens are detected                                                                | ADR 0004                                                                                                |
| Brute force                                     | No lockout                                                                                                                                     | 5 failures lock the account for 15 minutes, plus per-IP limits                                                                                                                               | Password guessing                                                                                                               | `login-throttle.js`, `rate-limits.js`                                                                   |
| Sign-in identifier                              | Username only                                                                                                                                  | Username or work email; a shared email is refused                                                                                                                                            | Staff remember their email; guessing between accounts would be unsafe                                                           | `auth.service.js` (`resolveAccount`)                                                                    |
| Forgotten password                              | No self-service reset (an administrator sets a new one)                                                                                        | Emailed one-time link, valid 30 minutes; same answer whether or not the account exists                                                                                                       | Fewer administrator resets without revealing accounts                                                                           | `auth.service.js`, `ih_password_reset`                                                                  |
| Password reset while both systems run           | n/a                                                                                                                                            | The new password is stored only in `ih_employee_password`, so the legacy app still accepts the old one until it is retired                                                                   | The legacy table stays read-only                                                                                                | ADR 0003                                                                                                |
| Two-factor sign-in                              | Email code                                                                                                                                     | Accounts with it enabled are refused (`TWO_FACTOR_REQUIRED`)                                                                                                                                 | Planned for a later phase; refusing is safer than skipping the factor                                                           | `auth.service.js`                                                                                       |
| Approval PIN                                    | Compared in the browser, plain text or BCrypt                                                                                                  | Verified by the API (same formats), never rewritten, 5 tries then a 15-minute lock                                                                                                           | Legacy screens still read the stored PIN                                                                                        | `auth.service.js` (`verifyApprovalPin`)                                                                 |
| Master permissions                              | Any of the five "Master" permissions opens every master screen; the server checks nothing                                                      | New "Masters View" (id 900001) shows master data; "Masters Entry" also changes it; checked by the API on every request                                                                       | A read-only role was missing; browser-only checks can be bypassed                                                               | `@ihealth/shared/permissions` (`POLICIES`), `apps/api/db/sql/additive/0003-masters-view-permission.sql` |
| Deleting master data                            | Hard delete endpoints (unused by the UI) and an `ACTIVE_S` radio                                                                               | Deactivate and restore only; nothing is deleted                                                                                                                                              | Keeps history and references intact                                                                                             | `apps/api/src/http/crud/create-crud-routes.js`                                                          |
| Duplicate master records                        | Not checked (some screens warn in the browser only)                                                                                            | Checked by the API, case-insensitively, inside the write transaction                                                                                                                         | Duplicates such as two "CIPLA" rows                                                                                             | `unique` rules per resource                                                                             |
| Email fields                                    | Only addresses ending in ".com" accepted                                                                                                       | Any valid address                                                                                                                                                                            | The old pattern rejected valid Kenyan addresses (.co.ke)                                                                        | `optionalEmail` in `@ihealth/shared/schemas`                                                            |
| Provider licence number                         | Required on the form, but most stored prescribers have none                                                                                    | Optional; duplicates refused only when one is entered                                                                                                                                        | A required field would block every edit of the existing records                                                                 | `providerInputSchema`                                                                                   |
| Provider date of birth                          | Editable                                                                                                                                       | Not shown or edited                                                                                                                                                                          | The column holds zero dates the new stack cannot read, and a prescriber's birth date is not needed to dispense                  | `apps/api/src/features/masters/providers.js`                                                            |
| Pharmacy logo                                   | Any file uploaded as multipart and stored as bytes                                                                                             | PNG, JPEG or WebP up to 1 MB, checked by its actual bytes; served with `nosniff`                                                                                                             | Stops non-images being stored and served as images                                                                              | `pharmacy-profile.js`                                                                                   |
| Legacy timestamps                               | Read with `zeroDateTimeBehavior=convertToNull`                                                                                                 | Never selected through the models; read with raw SQL when needed                                                                                                                             | Zero dates break every query that selects them                                                                                  | `apps/api/db/README.md`                                                                                 |
| Item description and pack                       | Required on the form, but most stored items have none                                                                                          | Optional                                                                                                                                                                                     | A required field would block every edit of the existing items                                                                   | `itemInputSchema`                                                                                       |
| Item schedule and Latin code                    | Blank picks saved as hardcoded ids 4 and 119 (placeholder rows with no code)                                                                   | Left empty when not chosen; the placeholder rows are not offered                                                                                                                             | No hardcoded ids; an empty value means the same thing                                                                           | `items.js`, `lookup-routes.js`                                                                          |
| Item pharmacy                                   | Always saved as pharmacy 1 (hardcoded in the browser)                                                                                          | This installation's pharmacy (`PHARMACY_ID`, else the first active one)                                                                                                                      | No hardcoded ids                                                                                                                | `current-pharmacy.js`                                                                                   |
| Item code and barcode                           | Not checked for duplicates                                                                                                                     | A new or changed code or barcode must not be in use                                                                                                                                          | Scanning a barcode must find one item                                                                                           | `items.js` (`unique`)                                                                                   |
| Item tax category                               | Every category offered, including retired rates                                                                                                | Only active rates                                                                                                                                                                            | A retired VAT rate must not be picked for a new item                                                                            | `/lookups/tax-categories`                                                                               |
| Item rack, shelf, storage and alert message     | Edited on the item form; rack and shelf were copied to every stock row                                                                         | Not on the item form                                                                                                                                                                         | Location belongs to each stock batch (Stock phase); the storage and alert lists were hardcoded in the browser                   | `items.js`                                                                                              |
| Supplier required fields                        | Phone, post code and contact person (name and phone) required on the form                                                                      | Optional; name, tax PIN, address line 1, country, province and return-credit type stay required                                                                                              | About a third of stored suppliers have no phone, post code or contact; requiring them would block editing those suppliers       | `supplierInputSchema`                                                                                   |
| Supplier tax PIN and name                       | Not checked for duplicates                                                                                                                     | A new or changed name or tax PIN must not be in use (case-insensitive)                                                                                                                       | Duplicate suppliers split purchase and payables history                                                                         | `suppliers.js` (`unique`)                                                                               |
| Supplier IFSC, MICR, CST and PIN numbers        | On the form                                                                                                                                    | Not on the form; stored values are kept                                                                                                                                                      | Indian banking and tax fields: unused by the Kenyan data (one value each at most)                                               | `suppliers.js`                                                                                          |
| Supplier permissions                            | Any Master permission opens the screen; nothing checked on the server                                                                          | Read with Masters View, Masters Entry or Update Supplier; changed with Masters Entry or Update Supplier, checked by the API                                                                  | Update Supplier now means exactly that                                                                                          | `POLICIES.suppliers`                                                                                    |
| Selects in forms                                | Values shown only if their list had loaded                                                                                                     | Selects are controlled and keep showing a stored choice, even an inactive one, marked "no longer offered"                                                                                    | Stored countries, units and other choices appeared empty on screen                                                              | `components/form/select-field.jsx`                                                                      |
| Customer required fields                        | Date of birth and postal code required on the full form (the till asked only name and phone)                                                   | Required: type, first name, phone, country, province. Date of birth and postal code optional                                                                                                 | 97% of stored customers have no date of birth and almost none a postal code; requiring them would block editing those customers | `customerInputSchema`                                                                                   |
| Customer phone numbers                          | Stored as typed                                                                                                                                | Saved without spaces or dashes; duplicates allowed                                                                                                                                           | Stored numbers have no spaces, so search by number finds them; family members share one phone (2,197 numbers are shared)        | `customerInputSchema`                                                                                   |
| Customer credit limit, credit days and discount | Edited on the customer (13 customers have values) but never read by sales; the till's credit checks use the separate credit (master) account   | Not on the customer form; stored values are kept                                                                                                                                             | Two places for the same limit would disagree; credit accounts belong to the Finance phase                                       | `customers.js`                                                                                          |
| Corporate customers                             | Company fields cleared in the browser when switching to individual                                                                             | The API clears them when a customer is saved as an individual; the legacy 'S' value (10 rows) is shown as individual                                                                         | One rule, enforced on the server                                                                                                | `customers.js`                                                                                          |
| Customer pharmacy                               | From the signed-in browser's storage (missing on 11,940 records)                                                                               | This installation's pharmacy, set by the API                                                                                                                                                 | No value trusted from the browser                                                                                               | `current-pharmacy.js`                                                                                   |
| Employee code                                   | Generated in the browser from a counter read, increased and saved without a lock (two people saving at once could get the same code); editable | Generated by the API in the save transaction with one atomic update, in the same format (prefix + EM + ddMMyy + 4 digits); read-only                                                         | Unique codes without a race                                                                                                     | `document-codes.js`                                                                                     |
| Document code prefix                            | Hardcoded "DP"                                                                                                                                 | `DOCUMENT_CODE_PREFIX` setting (default DP)                                                                                                                                                  | No hardcoded values                                                                                                             | `config/env.js`                                                                                         |
| Employee salary, documents and photo            | On the employee form (salary required)                                                                                                         | Not on the employee record; stored values are kept                                                                                                                                           | HR and payroll data, not needed to run the pharmacy; it should not be visible to everyone who can see staff records             | `employees.js`                                                                                          |
| Employee required fields                        | Postal code, NSSF, title and others required                                                                                                   | Same, but province, employment type and blood group optional where the stored data lacks them (rule: required when nearly every record, 90% or more, has it)                                 | A required field most records lack would block editing them                                                                     | `employeeInputSchema`                                                                                   |
| Full or part time                               | Free text ("full", "Part time", ...)                                                                                                           | A choice, written as "Full time" or "Part time"; stored variants are read case-insensitively                                                                                                 | Consistent data                                                                                                                 | `employees.js`                                                                                          |
| Employee NSSF number                            | Not checked for duplicates                                                                                                                     | A new or changed NSSF number must not be in use                                                                                                                                              | One NSSF number belongs to one person                                                                                           | `employees.js` (`unique`)                                                                               |
| Must change password                            | `PASSWORD_STATUS` column, set on 3 of 56 accounts, meaning undocumented                                                                        | An administrator can require a new password at the next sign-in (`ih_password_change_required`); until it is changed the API refuses every request except sign-out and changing the password | A temporary password should not stay in use; enforced on the server                                                             | `account-admin.service.js`, `auth.guards.js`, `0004-password-change-required.sql`                       |
| Administrator password reset                    | Typed into the employee form and saved to the legacy column                                                                                    | Saved as argon2id in `ih_employee_password`; all the employee's sessions end; a lockout is lifted                                                                                            | Same password storage as everywhere else; a reset must sign out anyone using the old password                                   | `account-admin.service.js`                                                                              |
| Creating a sign-in                              | Username and password saved in `employee_credentials`                                                                                          | Same row, but its legacy password column gets a random value no one knows; the real password is only in `ih_employee_password`                                                               | The legacy column is never written with a real password                                                                         | `account-admin.service.js`                                                                              |
| Changing one's own access                       | An administrator could edit their own permissions and role                                                                                     | Refused (sign-in on/off, password, role, permissions, two-factor) for one's own account; another administrator must do it                                                                    | Nobody can lock themselves out or grant themselves more access                                                                  | `account-admin.service.js`                                                                              |
| Employee roles                                  | An employee could hold several role rows                                                                                                       | Saving a role keeps one row (the first, updated) and removes the others; the branch is this installation's pharmacy                                                                          | Access that is easy to follow; there is no branch table and every stored row uses branch 1                                      | `account-admin.repository.js`                                                                           |
| Individual permissions                          | Saved by the browser as a list                                                                                                                 | Set exactly by the API; rows are switched on or off (`ACTIVE_S`), never deleted; unknown ids are refused                                                                                     | Keeps history; never trusts the browser                                                                                         | `account-admin.repository.js`                                                                           |
| Two-factor reset                                | Administrator reset with a reason                                                                                                              | Same steps as the legacy reset (trusted devices revoked, enrolment cleared, open codes closed, reset logged)                                                                                 | Kept identical so both systems agree                                                                                            | `account-admin.repository.js`                                                                           |
| Item-supplier duplicates                        | Not checked: the same item and supplier could be linked many times                                                                             | Refused on create and when an edit changes the item or supplier; old duplicates stay editable and are flagged "Linked twice"                                                                 | Purchase orders pick a supplier's rate from the link; two links give two rates                                                  | `apps/api/src/features/masters/item-suppliers.js`                                                       |
| Item-supplier links to deleted records          | Not checked; links to missing items fail silently in the joined lists                                                                          | Refused for new links; old ones are listed (not hidden) and flagged "Item gone" / "Supplier gone"                                                                                            | Visible so they can be cleaned up                                                                                               | `item-suppliers.js` (`assertLinkedRecordsExist`, `linksWithMissingRecords`)                             |
| Item-supplier terms                             | Priority optional; rate and discount any number with up to two decimals (some stored discounts are above 100%); validity required              | Priority 1–3 required; rate 0–10,000,000 and discount 0–100%, two decimals; validity required, today's date by default; old values outside these limits are shown as stored                  | The column cannot be empty; a discount above 100% is a data-entry error                                                         | `@ihealth/shared/schemas` (`itemSupplierInputSchema`)                                                   |
| Clean-up for the data migration (not done here) | n/a                                                                                                                                            | Dev copy: 18 item-supplier pairs stored twice (41 rows), 9 links to items that no longer exist, 596 links without a priority, 25 discounts above 100%. Nothing is changed in the data        | To be decided and scripted with the migration, on a copy                                                                        | Filter "Old data" on Masters › Item suppliers                                                           |
| Saving master records                           | Saved at once when Save was clicked                                                                                                            | Asks "Save these changes?" with each change as before → after; Save is off until something changes                                                                                           | Mistaken edits to stock and price data are costly                                                                               | `apps/web/src/features/masters/record-dialog.jsx`                                                       |
| Masters not in phase 1                          | Insurance, Membership, Configuration and Account screens under Masters                                                                         | Not rebuilt yet; the legacy app still serves them                                                                                                                                            | To be planned with their owners before they are rebuilt                                                                         | —                                                                                                       |
