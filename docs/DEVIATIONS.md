# Deviations from the legacy system

Every intentional difference in behaviour between the legacy iHealth system and this rebuild, and why.
Each entry names where it is implemented. Add a row with every pull request that changes behaviour.

| Area                                        | Legacy behaviour                                                                          | New behaviour                                                                                                              | Why                                                                                                            | Where                                                                                                   |
| ------------------------------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Permissions                                 | Checked in the Angular app only, by position in a list (`permissions[25]`)                | Checked by the API on every request, by `PHARMA_ACCESS_ID`                                                                 | Browser checks can be bypassed; positions break when rows change                                               | `apps/api/src/features/auth/auth.guards.js`, `@ihealth/shared/permissions`                              |
| Role permissions                            | None (only per-employee grants)                                                           | `ih_role_permission`, empty by default                                                                                     | Role-based access without changing existing grants                                                             | `apps/api/db/sql/additive/0001-auth.sql`                                                                |
| Password storage                            | BCrypt or plain text in `employee_credentials`                                            | argon2id in `ih_employee_password`, upgraded at sign-in; the legacy column is never written                                | Plain text is unacceptable for health data; the legacy app keeps working                                       | `apps/api/src/features/auth/auth.service.js`                                                            |
| Session                                     | JWT readable by page scripts                                                              | httpOnly cookies, 15-minute access token, rotating refresh token, CSRF token                                               | XSS cannot steal the session; stolen refresh tokens are detected                                               | ADR 0004                                                                                                |
| Brute force                                 | No lockout                                                                                | 5 failures lock the account for 15 minutes, plus per-IP limits                                                             | Password guessing                                                                                              | `login-throttle.js`, `rate-limits.js`                                                                   |
| Sign-in identifier                          | Username only                                                                             | Username or work email; a shared email is refused                                                                          | Staff remember their email; guessing between accounts would be unsafe                                          | `auth.service.js` (`resolveAccount`)                                                                    |
| Forgotten password                          | No self-service reset (an administrator sets a new one)                                   | Emailed one-time link, valid 30 minutes; same answer whether or not the account exists                                     | Fewer administrator resets without revealing accounts                                                          | `auth.service.js`, `ih_password_reset`                                                                  |
| Password reset while both systems run       | n/a                                                                                       | The new password is stored only in `ih_employee_password`, so the legacy app still accepts the old one until it is retired | The legacy table stays read-only                                                                               | ADR 0003                                                                                                |
| Two-factor sign-in                          | Email code                                                                                | Accounts with it enabled are refused (`TWO_FACTOR_REQUIRED`)                                                               | Planned for a later phase; refusing is safer than skipping the factor                                          | `auth.service.js`                                                                                       |
| Approval PIN                                | Compared in the browser, plain text or BCrypt                                             | Verified by the API (same formats), never rewritten, 5 tries then a 15-minute lock                                         | Legacy screens still read the stored PIN                                                                       | `auth.service.js` (`verifyApprovalPin`)                                                                 |
| Master permissions                          | Any of the five "Master" permissions opens every master screen; the server checks nothing | New "Masters View" (id 900001) shows master data; "Masters Entry" also changes it; checked by the API on every request     | A read-only role was missing; browser-only checks can be bypassed                                              | `@ihealth/shared/permissions` (`POLICIES`), `apps/api/db/sql/additive/0003-masters-view-permission.sql` |
| Deleting master data                        | Hard delete endpoints (unused by the UI) and an `ACTIVE_S` radio                          | Deactivate and restore only; nothing is deleted                                                                            | Keeps history and references intact                                                                            | `apps/api/src/http/crud/create-crud-routes.js`                                                          |
| Duplicate master records                    | Not checked (some screens warn in the browser only)                                       | Checked by the API, case-insensitively, inside the write transaction                                                       | Duplicates such as two "CIPLA" rows                                                                            | `unique` rules per resource                                                                             |
| Email fields                                | Only addresses ending in ".com" accepted                                                  | Any valid address                                                                                                          | The old pattern rejected valid Kenyan addresses (.co.ke)                                                       | `optionalEmail` in `@ihealth/shared/schemas`                                                            |
| Provider licence number                     | Required on the form, but most stored prescribers have none                               | Optional; duplicates refused only when one is entered                                                                      | A required field would block every edit of the existing records                                                | `providerInputSchema`                                                                                   |
| Provider date of birth                      | Editable                                                                                  | Not shown or edited                                                                                                        | The column holds zero dates the new stack cannot read, and a prescriber's birth date is not needed to dispense | `apps/api/src/features/masters/providers.js`                                                            |
| Pharmacy logo                               | Any file uploaded as multipart and stored as bytes                                        | PNG, JPEG or WebP up to 1 MB, checked by its actual bytes; served with `nosniff`                                           | Stops non-images being stored and served as images                                                             | `pharmacy-profile.js`                                                                                   |
| Legacy timestamps                           | Read with `zeroDateTimeBehavior=convertToNull`                                            | Never selected through the models; read with raw SQL when needed                                                           | Zero dates break every query that selects them                                                                 | `apps/api/db/README.md`                                                                                 |
| Item description and pack                   | Required on the form, but most stored items have none                                     | Optional                                                                                                                   | A required field would block every edit of the existing items                                                  | `itemInputSchema`                                                                                       |
| Item schedule and Latin code                | Blank picks saved as hardcoded ids 4 and 119 (placeholder rows with no code)              | Left empty when not chosen; the placeholder rows are not offered                                                           | No hardcoded ids; an empty value means the same thing                                                          | `items.js`, `lookup-routes.js`                                                                          |
| Item pharmacy                               | Always saved as pharmacy 1 (hardcoded in the browser)                                     | This installation's pharmacy (`PHARMACY_ID`, else the first active one)                                                    | No hardcoded ids                                                                                               | `current-pharmacy.js`                                                                                   |
| Item code and barcode                       | Not checked for duplicates                                                                | A new or changed code or barcode must not be in use                                                                        | Scanning a barcode must find one item                                                                          | `items.js` (`unique`)                                                                                   |
| Item tax category                           | Every category offered, including retired rates                                           | Only active rates                                                                                                          | A retired VAT rate must not be picked for a new item                                                           | `/lookups/tax-categories`                                                                               |
| Item rack, shelf, storage and alert message | Edited on the item form; rack and shelf were copied to every stock row                    | Not on the item form                                                                                                       | Location belongs to each stock batch (Stock phase); the storage and alert lists were hardcoded in the browser  | `items.js`                                                                                              |
